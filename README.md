# Tender Parser — автоматический анализ тендеров

Программа принимает архив с тендерами, извлекает из документов текст и с помощью ИИ заполняет таблицу Excel (поля указываются в файле config.yaml).

Каждая закупочная позиция тендера — отдельная строка в таблице. Общие поля тендера (НМЦ, заказчик, сроки и т.д.) дублируются в каждой строке этого тендера — так удобнее для фильтров и сводных таблиц Excel.

---

## Что нужно установить один раз

### 1. Python
Скачайте и установите с сайта [python.org](https://python.org) (версия 3.10 или новее).

### 2. unar — для работы с RAR-архивами

**Mac:**
```bash
brew install unar
```

**Windows:** скачайте `unrar.exe` с [rarlab.com](https://www.rarlab.com/rar_add.htm) и добавьте папку с ним в системный PATH.

### 3. LibreOffice — для чтения старых .doc файлов
Скачайте и установите с сайта [libreoffice.org](https://libreoffice.org) (бесплатно).

---

## Первый запуск — настройка проекта

Откройте терминал, перейдите в папку с программой и выполните по очереди:

```bash
# Создать виртуальное окружение
python -m venv .venv

# Активировать его
# На Mac / Linux:
source .venv/bin/activate
# На Windows:
.venv\Scripts\activate
```

После этого в начале строки терминала появится `(.venv)`.

```bash
# Установить все зависимости
pip install -r requirements.txt
```

## Настройка

### Изменить список полей в Excel

Откройте файл `config.yaml` и найдите раздел `fields`. Каждый элемент — это одна колонка в итоговой таблице (или несколько колонок, если поле списочное).

**Обычное поле** — одно значение на тендер, одна колонка в Excel:
```yaml
  - name: месяц_торгов
    description: месяц проведения торгов в формате "Месяц Год"
```

**Поле-список** (`type: list`) — массив объектов. Каждый объект → отдельная строка Excel, общие поля тендера в этой строке дублируются. Подполя из `item_schema` становятся отдельными колонками:
```yaml
  - name: позиции
    type: list
    item_schema:
      - {key: название,    column: позиции}
      - {key: количество,  column: количество штук,        numeric: true}
      - {key: цена_за_шт,  column: цена за штуку,          numeric: true}
      - {key: цена_итого,  column: общая цена за позицию,  numeric: true}
    description: |
      массив закупочных позиций тендера. Каждый элемент — объект с полями:
      название, количество, цена_за_шт, цена_итого.
```
Флаг `numeric: true` означает что подполе пишется в Excel как число (int/float), а не строка — тогда работают формулы `СУММ`, `СРЗНАЧ`, сводные таблицы.

Чтобы **добавить поле** — добавьте новый элемент с `name` и `description`. Чтобы **убрать поле** — удалите или закомментируйте строки. Больше ничего менять не нужно — промпт и колонки Excel обновятся автоматически. Сейчас в конфиге **7 полей**: `позиции`, `месяц_торгов`, `месяц_работ`, `время_выполнения`, `общая_цена`, `категория_заказчика`, `начальная_цена`.

### Изменить инструкцию для ИИ (промпт)

Промпт — это инструкция, которую программа отправляет в ИИ вместе с текстом тендера. Лежит в файле `prompts/analyze_tender.txt`. Там описаны общие правила: откуда брать данные, что не выдумывать, как форматировать числа и т.п.

**Важно:** в промпте есть специальное слово `{fields_schema}` — это плейсхолдер. Перед отправкой в ИИ программа автоматически заменяет его на список всех полей из `config.yaml` (имя поля + описание + JSON-шаблон). Поэтому **поля в промпте вручную прописывать не нужно** — достаточно оставить `{fields_schema}` на своём месте, и при каждом запуске туда подставятся актуальные поля.

При редактировании промпта **обязательно сохраните**:
- `{fields_schema}` — иначе ИИ не получит список полей и вернёт пустой результат
- строку `Текст тендера:` в самом конце — это маркер, после которого программа дописывает сам текст тендера

**Можно править свободно:**
- общие правила для ИИ (откуда брать данные, что не придумывать, как трактовать форматы)
- порядок и формулировки правил
- описания категорий заказчика, форматов чисел и т.п.

Пример: если хотите чтобы ИИ всегда возвращал суммы с двумя знаками после запятой — добавьте правило вроде «числовые поля всегда с двумя знаками после запятой, даже если в тексте указано целое число».

### Для работы через локальную модель (Ollama) (не рекомендуется)
Установите [Ollama](https://ollama.com) и скачайте модель:
```bash
ollama pull gemma3:4b
```
Больше ничего не нужно — ключи не требуются.

### Для работы через интернет (OpenRouter / ChatGPT / ...)
Скопируйте файл с настройками и вставьте ключ:
```bash
cp .env.example .env
```
Откройте файл `.env` в любом текстовом редакторе и замените `sk-...` на ваш ключ API.

## Как запустить

Убедитесь что виртуальное окружение активировано (в начале строки есть `(.venv)`).

### Шаг 1 — проверить что текст извлекается правильно

```bash
python tender.py --input /путь/до/архива.rar
```

Программа создаст рядом с архивом папку `архив_parsed/` и положит туда `.txt`-файлы с текстом каждого тендера.

### Шаг 2 — анализ через локальную модель

```bash
python tender.py --input /путь/до/архива.rar --mode ollama
```

### Шаг 3 — анализ через интернет (быстрее и точнее)

```bash
python tender.py --input /путь/до/архива.rar --mode api
```

Результат — файл `result.xlsx` в той же папке `архив_parsed/`. Открывается в Excel или Google Таблицах.

## Если что-то пошло не так

**`logs/errors.log`** — все ошибки и пропуски тендеров: повреждённые архивы, отсутствующий LibreOffice, API-ошибки и т.д. Формат: `дата | файл | причина`.

**`logs/llm_debug.log`** — сырые ответы модели для тендеров, которые были пропущены по причине «модель вернула менее 3 полей». Полезно когда нужно понять что именно вернула модель — обрезанный JSON, пустой ответ, мусор. Помогает диагностировать сбои на стороне API-провайдера.

Если архив большой и вы хотите сначала обработать несколько тендеров для проверки — просто остановите программу (`Ctrl+C`) и откройте уже созданный `result.xlsx`.

---

## Повторный запуск

Если `.txt`-файлы уже созданы — она не будет извлекать текст заново, а сразу перейдёт к анализу. Если в `result.xlsx` уже есть строки — дозапишет только новые, не сотрёт старые.

---

## Пример типичной работы

```
# Шаг 1 — смотрим на качество текста
python tender.py --input ~/Downloads/Деревья.rar

# Всё хорошо, запускаем анализ
python tender.py --input ~/Downloads/Деревья.rar --mode ollama

# Открываем результат
open ~/Downloads/Деревья_parsed/result.xlsx
```
